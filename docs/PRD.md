# PRD — 발로란트 내전 도우미 (가칭)

> 발로란트 내전에서 팀 짜기 · 맵 선택 · 공수 정하기를 링크 하나로 빠르게 끝내는 웹앱.
> 이 문서는 구현용 스펙이다. 구현 시 이 문서를 기준으로 하고, 문서와 다른 결정을 하면 문서도 함께 수정한다.

---

## 1. 개요

### 1.1 배경
- 내전을 할 때마다 디스코드에서 손으로 팀을 나누고, 맵과 공수를 정하는 게 번거롭다.
- 티어만 보고 팀을 나누면 픽창에서 "1선(타격대) 할 사람이 없다", "연막(전략가) 할 사람이 없다" 같은 상황이 자주 생긴다.

### 1.2 목표
- 방 생성부터 팀·맵·공수 결정까지 **1분 이내**.
- 티어 균형뿐 아니라 **역할 구성까지 고려한 팀 자동 생성**.
- 로그인 없이 **방 코드/링크만으로** 여러 명이 동시에 사용.
- 방장 혼자 전부 입력해도 되고, 참가자가 **각자 자기 정보를 입력**해도 된다.

### 1.3 대상 사용자
- 친구들끼리 내전을 하는 발로란트 유저

## 2. 용어

| 용어 | 의미 | 코드 표기 |
|---|---|---|
| 방 | 한 번의 내전 세션 단위 | `room` |
| 방 코드 | 참가자에게 공유하는 6자리 코드 | `room.code` |
| 방장 키 | 방장 권한을 증명하는 비밀 값 | `host_key` |
| 멤버 | 방에 등록된 플레이어 | `member` |
| 수정 토큰 | 등록한 참가자에게만 주는 비밀 값. 본인 정보 수정·삭제 권한 증명 | `edit_token` |
| 권한 구분 | 방장 / 참가자 | `userType: 'host' \| 'participant'` |
| 포지션 | 게임 내 역할 (타격대 등) | `position` |
| 숙련도 | 포지션별 주력/가능/불가 | `proficiency: 'main' \| 'can' \| 'no'` |

> 방장/참가자 구분과 게임 역할을 혼동하지 않도록 **게임 역할은 반드시 `position`** 으로 표기한다.

포지션 키:

| key | 표시명 |
|---|---|
| `duelist` | 타격대 |
| `initiator` | 척후대 |
| `controller` | 전략가 |
| `sentinel` | 감시자 |

## 3. 사용자 흐름

```
[초기 페이지]
 ├─ [방 파기] → 방 코드 + 방장 키 생성 → 방장 화면
 └─ [참가하기] → 코드 입력 → 참가자 화면
     (또는 /join/ABC123 링크 클릭 → 참가자 화면)

[참가자 화면]
 ├─ 첫 진입 시 정보 입력 (이미 등록한 기기면 건너뜀) → 멤버 목록
 ├─ 내 정보 수정·삭제
 └─ 멤버 목록 / 팀(내 팀·시작 진영) / 맵 / 공수 결과 실시간 보기

[방장 화면]
 ├─ 멤버 추가·수정·삭제
 ├─ 멤버 목록
 ├─ [팀 짜기]   ← 독립 기능
 ├─ [맵]        ← 독립 기능 (방장이 최대 2밴 → 랜덤)
 ├─ [공수]      ← 독립 기능 (랜덤)
 └─ 결과 디코용 텍스트 복사
```

**팀 짜기 · 맵 · 공수는 서로 독립적으로 동작한다.** 팀을 짜지 않아도 맵·공수만 돌릴 수 있고, 판마다 맵·공수만 다시 돌릴 수 있다.

## 4. 기능 요구사항

### F1. 초기 페이지 (`/`)
- **F1-1** [방 파기] 버튼: 새 방 생성 → 방장 화면으로 이동.
- **F1-2** [참가하기]: 6자리 코드 입력 → 존재하는 방이면 참가자 화면으로 이동, 없으면 "방을 찾을 수 없어요" 에러.
- **F1-3** 코드 입력은 대소문자 구분 없이 받고 내부적으로 대문자로 정규화.

**수용 기준**
- 방 파기 후 2초 이내에 방장 화면 진입.
- 존재하지 않거나 만료된 코드 입력 시 에러 메시지 표시, 페이지 이동 없음.

### F2. 방 생성 · 입장
- **F2-1** 방 코드: 6자리, 문자셋 `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (헷갈리는 `0 O 1 I L` 제외).
- **F2-2** 코드는 DB 유니크. 충돌 시 서버에서 재생성 (최대 5회).
- **F2-3** 방장 키: 충분히 긴 랜덤 값(UUID 이상). 방 코드와 별도.
- **F2-4** 방장 키는 방장 브라우저 `localStorage`에 `host_key:{code}` 로 저장.
- **F2-5** ~~[방장 링크 복사] 버튼~~ — 화면에서 뺐다 (2026-10-08). `/room/{code}/host#key={host_key}` 로 열면 키를 localStorage에 저장하고 fragment 를 지우는 처리는 그대로 남아 있다.
- **F2-6** 방장 화면에 **[참가 링크 복사]** 버튼: `/join/{code}`.
- **F2-7** `/join/{code}` → `/room/{code}` 로 리다이렉트.
- **F2-8** 방장 화면 진입 시 localStorage에 유효한 방장 키가 없으면 참가자 화면으로 보낸다.
- **F2-9** 방은 생성 후 **24시간이 지나면 삭제**. 관련 데이터 전부 cascade 삭제.

### F3. 멤버 등록 · 수정

**멤버 필드**

| 필드 | 필수 | 비고 |
|---|---|---|
| 닉네임 | O | 1~16자, 방 내 중복 불가 |
| 현티 | O | 티어 선택 또는 `언랭` |
| 최티 | X | 비우면 현티와 같게 계산. 현티가 `언랭`이면 최티 필수 |
| 포지션 숙련도 | X | 4개 포지션 각각 `main / can / no`, 기본값 전부 `can`. **선택사항** — 하나도 안 고르면(전부 `can`) 포지션 칸을 **공백**으로 둔다 |

**입력 UI**
- **F3-1** 티어 선택은 아이콘/버튼 탭 방식 (드롭다운 지양). 티어 그룹 선택 → 단계(1/2/3) 선택.
- **F3-2** 포지션은 아이콘 4개 탭 토글: 탭할 때마다 `can → main → no → can` 순환. 선택사항이며 안 건드리면 공백. 하나라도 바꿨으면 [선택 해제] 표시.
  - 목록 요약: 선택 안 했으면 공백, 주력이 있으면 주력 포지션들, 주력 없이 불가만 있으면 가능한 포지션들.
- **F3-3** 텍스트 입력은 닉네임 하나뿐.

**방장**
- **F3-4** 멤버 추가·수정·삭제 모두 가능.
- **F3-5** 멤버 추가: [추가] 버튼 하나. 누르면 바로 멤버 정보 입력 폼(닉네임·현티·최티·포지션)이 열린다 (PC 모달 / 모바일 하단 시트, 수정 폼과 같은 컴포넌트, `upsert_member_as_host` 에 `member_id = null`).
  - 폼 하단 [저장] / [저장하고 하나 더]. 저장하고 하나 더는 저장 후 폼을 비우고 닉네임 입력에 포커스 (연속 입력).
  - 닉네임 중복(`NICKNAME_TAKEN`)이면 폼에 "이미 있는 닉네임이에요", 입력값 유지.
  - 닉네임만 줄 단위로 붙여넣는 일괄 등록은 없앴다 (DB 함수 `bulk_add_members` 는 남아 있지만 화면에서 쓰지 않음).

**참가자**
- **F3-6** 첫 진입 시 정보 입력 화면 표시. 이미 등록한 기기면 건너뛰고 멤버 목록 + "내 정보" 카드를 보여준다. 방장이 등록해둔 항목을 이어받는 기능("이거 나임")은 없다.
- **F3-7** 등록하면 서버가 `edit_token` 발급 → localStorage `member:{code}` 에 `{ id, token }` 저장. (쿠키 아님 — RPC 인자로 토큰을 넘기므로 httpOnly 의미 없음)
- **F3-8** 다음 진입 시 `member:{code}` 가 있으면 입력 화면을 건너뛴다. 저장된 id 가 멤버 목록에 없으면(방장이 삭제) 지우고 입력 화면으로.
- **F3-9** 참가자는 **본인 정보만** 수정·삭제 가능 (토큰으로 확인). 방장은 전체 수정·삭제 가능. 다른 멤버 행에는 수정·삭제 버튼이 없다.
  - 삭제는 화면 안 확인 단계를 거친다: "내 정보를 삭제할까요? 다시 참가하려면 새로 입력해야 해요". 성공하면 `member:{code}` 를 지우고 입력 화면으로.
  - 닉네임 중복(`NICKNAME_TAKEN`): "이미 있는 닉네임이에요. 방장이 등록해뒀다면 방장에게 수정을 부탁하세요"
  - 토큰 불일치(`FORBIDDEN`): `member:{code}` 를 지우고 "내 정보를 찾을 수 없어요. 다시 입력해주세요" 토스트 후 입력 화면으로.
  - 화면 분기는 표시용일 뿐이고 실제 권한 검사는 RPC 에서 한다.

> **왜 member_id 만으로는 안 되나**: `members` 는 공개 테이블(anon SELECT)이라 누구나 남의 id 를 알 수 있다. id 만으로 수정·삭제를 허용하면 남의 정보를 건드릴 수 있으므로, 등록한 사람에게만 주는 비밀 토큰(`edit_token`)으로 확인한다.

**충돌 처리**
- **F3-10** 방장과 참가자가 같은 멤버를 동시에 수정하면 **마지막 저장이 우선** (last write wins).

### F4. 멤버 목록 (방장)
- **F4-1** 방의 멤버 목록을 보여주고 [팀 짜기] 버튼을 둔다. 별도의 참가자 체크(선택) 기능은 없다 — 방에 등록된 멤버 전원이 팀 짜기 대상.
- **F4-2** 멤버가 정확히 10명이어야 [팀 짜기] 활성화. 아니면 "멤버가 10명이어야 해요 (현재 N명)" 표시. 인원 조정은 멤버 추가·삭제로 한다.
- **F4-3** 티어 미입력 멤버가 있으면 팀 짜기 비활성 + 해당 멤버 표시.

### F5. 팀 짜기 (방장, 독립 기능)
- **F5-1** 방 멤버 10명으로 5:5 팀 자동 생성 (알고리즘은 §6).
- **F5-2** 결과: 팀1 / 팀2, 각 멤버의 **추천 포지션**, 팀별 점수 합.
- **F5-3** 어떤 팀이든 4개 포지션 중 채울 수 없는 포지션이 있으면 경고 표시. 예: "팀2: 전략가 가능 인원 없음".
- **F5-4** 팀 결과는 DB에 저장하지 않고 **방장 브라우저 localStorage** `teams:{code}` 에 저장한다. 새로고침해도 유지되고, **[팀 다시 짜기]를 눌러야만 바뀐다**. 참가자에게는 팀 구성(멤버 id)만 공유한다 (F5-7).
- **F5-5** 처음 누르면 최적 조합, **[팀 다시 짜기]를 누를 때마다 다음으로 좋은 조합** (비용 순 상위 10개를 차례로, 끝나면 처음으로). 화면에 "N/10번째 조합 · 점수 차" 표시. 멤버 정보가 바뀌었으면 다음 클릭에서 새로 계산.
- **F5-6** 선수 교체: 팀 결과의 [선수 교체] → 교체 모드 ("바꿀 두 명을 차례로 선택하세요" + [완료]).
  - 첫 번째로 고른 선수는 accent 테두리. 다른 팀 선수를 고르면 두 명 자리 교체. 같은 팀 선수를 고르면 선택만 그 사람으로, 같은 사람을 다시 누르면 선택 해제. 여러 번 연속 교체 가능, [완료]로 종료.
  - 교체할 때마다 팀별 점수 합, 추천 포지션 배정, 포지션 부족 경고를 다시 계산 (자동 생성과 같은 팀 단위 배정 함수 `buildTeam`).
  - [되돌리기]: 자동 생성 직후 결과로 복원. [팀 다시 짜기]를 누르면 교체는 초기화된다.
  - 디코용 복사 텍스트는 교체된 결과 기준.
  - 교체 결과는 localStorage 에 저장하지 않는다. 대신 F5-7 로 공유된 구성이 자동 생성 결과와 같은 10명을 다르게 나눈 것이면 새로고침 후 교체 결과로 복원한다.
  - 행은 버튼 (`aria-pressed` 로 선택 상태), 키보드로도 교체 가능.
- **F5-7** 팀 공유: 방장이 [팀 짜기 / 팀 다시 짜기], 선수 교체, [되돌리기] 할 때마다 지금 화면의 팀 구성(팀1·팀2 멤버 id 5명씩)을 `set_teams` 로 `rooms.team1_ids / team2_ids` 에 저장 → 실시간 반영.
  - 참가자 화면은 이 구성을 현재 멤버 정보로 `buildTeam` 해서 팀 카드(점수 합·추천 포지션)를 보여준다. 공수 결과가 있으면 팀 카드에 시작 진영(공격/수비) 배지.
  - **내 팀** 카드: "팀1 · 공격 시작" 처럼 내 팀과 시작 진영 (공수 안 돌렸으면 "공수 미정"). 내가 팀에 없으면 "이번 팀에는 없어요". 팀 카드에서 내 행 강조.
  - 공유된 멤버가 삭제됐거나 티어가 지워졌으면 참가자 화면에 팀을 숨긴다 (방장이 다시 짤 때까지).
  - 방장 화면 팀 카드에도 시작 진영 배지.

### F6. 맵 (독립 기능)
- **F6-1** 방마다 **맵 풀**을 가짐. 기본값은 상수 `DEFAULT_MAP_POOL` (현재 경쟁전 맵 풀). 방장이 체크박스로 켜고 끄기.
  - 2026-10 기준 (2026 Act 5): 어비스, 어센트, 헤이븐, 로터스, 스플릿, 서밋, 선셋. 액트마다 `src/lib/constants/maps.ts` 갱신.
- **F6-2** 밴은 **방장만** 한다. 팀별 밴은 디스코드에서 말로 정하고, 방장이 맵 풀 중 **0~2개**를 탭해서 밴으로 표시 (다시 탭하면 해제). 밴 선택은 방장 클라이언트 상태로만 관리 (저장 불필요).
- **F6-3** 방장이 **[맵 랜덤]** 클릭 → 서버가 맵 풀에서 밴 맵을 뺀 나머지 중 **랜덤 1개** 선택 → 밴 목록과 결과 저장 → 모든 클라이언트에 실시간 반영.
- **F6-4** 언제든 다시 돌릴 수 있음. [맵 다시 돌리기]를 누를 때마다 **서버에서 새로 랜덤** (같은 맵이 다시 나올 수도 있음). 최신 결과만 유지.
- **F6-5** 맵 풀이 비어 있거나 밴 후 남은 맵이 0개면 에러 표시, 확정하지 않음.
- **F6-6** 결과 공개 시 연출(§F8) 후 확정 맵 표시. 참가자 화면에는 밴된 맵과 결과만 보인다.

### F7. 공수 (독립 기능)
- **F7-1** 방장이 **[공수 랜덤]** 클릭 → 서버에서 팀1의 시작 진영(`attack` / `defense`) 랜덤 결정 → 실시간 반영.
- **F7-2** 표시: "팀1 공격 / 팀2 수비 시작" 형태.
- **F7-3** 언제든 다시 돌릴 수 있음. 누를 때마다 서버에서 새로 랜덤. 최신 결과만 유지.
- **F7-4** 결과 공개 시 연출(§F8) 후 확정 표시.

### F8. 결과 연출 (맵 · 공수 공통)
- **F8-1** 후보(맵 카드들 / 공격·수비 2칸) 사이를 하이라이트가 하나씩 이동하다가 점점 느려지며 멈춘다. **멈춘 칸이 확정 결과.**
- **F8-2** 결과는 서버에서 이미 결정돼 있고, 연출은 그 위치에 멈추도록 계산만 한다.
  - 총 이동 칸 수 = `후보 수 × 2~3바퀴 + 결과 위치까지 남은 칸`
  - 칸 간 간격 50ms → 300ms로 점점 증가 (ease-out)
- **F8-3** 연출 중 화면 탭/클릭 시 즉시 결과로 스킵.
- **F8-4** 연출 시간 약 1.5~2초.
- **F8-5** `prefers-reduced-motion` 이면 연출 없이 결과만 표시.
- **F8-6** 같은 결과(같은 roll id)에 대해 연출은 한 번만. 새로고침 후 다시 들어오면 연출 없이 결과만.

### F9. 결과 복사 (방장)
- **F9-1** [디코용 복사] 버튼 → 클립보드에 텍스트 복사, 완료 토스트.
- **F9-2** 존재하는 정보만 포함 (팀 안 짰으면 팀 섹션 생략 등).

예시:

### F10. 디스코드 자동 전송 (방장)
기능 플래그 `NEXT_PUBLIC_DISCORD_ENABLED=true` 일 때만. 꺼져 있으면 관련 UI 와 `/api/discord/*` 가 전부 숨겨진다(404). 봇은 쓰지 않고 **Discord OAuth2 `webhook.incoming`** 으로 채널 웹훅을 받는다.

- **F10-1** 연결: 방장 헤더 [디스코드 연결] → `POST /api/discord/start` (방장 확인 `verify_host`, state 를 httpOnly 쿠키 10분에 저장) → 디스코드 인가 화면에서 서버·채널 선택 → `GET /api/discord/callback` (state 비교, 쿠키 즉시 삭제, code → 토큰 교환) → 응답의 웹훅 id/token 과 서버 이름만 `set_discord_webhook` 으로 저장 (액세스 토큰은 저장하지 않음) → `/room/{code}/host?discord=connected|cancelled|error`. 방장 화면은 쿼리를 토스트로 보여주고 URL 에서 지운다.
- **F10-2** 표시: 연결되면 헤더 칩 "OO 서버 연결됨" (서버 이름을 모르면 "디스코드 연결됨"). 칩 → 시트: 자동 전송 켜기/끄기, [연결 해제].
- **F10-3** 자동 전송 (수동 [디코로 보내기] 버튼은 없다): 방장 브라우저 `localStorage["discord_auto:{code}"]` (기본 켬).
  - 팀 · 맵 · 공수 중 하나가 새로 정해질 때마다 확인한다. 하나라도 없으면 보내지 않는다.
  - 이번 결과로 **셋이 처음 다 갖춰지면 `all`** 로 한 번에, **이미 셋 다 있었으면 바뀐 것만** (`teams` / `map` / `side`) 보낸다.
  - 새로 정해지는 시점: [팀 짜기 / 팀 다시 짜기], 선수 교체 [완료] ([선수 교체] 를 눌렀을 때와 구성이 달라졌을 때만), 맵 랜덤 결과, 공수 랜덤 결과.
  - 결과 연출(F8)이 생기면 연출이 끝난 뒤 보낸다. 지금은 연출이 없어 결과가 나오면 바로 보낸다.
- **F10-4** 전송 성공/실패는 토스트로 알린다 (예: "디스코드로 보냈어요", 전송 제한이면 "N초 뒤 다시 시도").
- **F10-5** 전송 `POST /api/discord/send` `{ code, hostKey, kind: teams|map|side|all, teams? }`
  - 맵 · 공수는 서버가 `rooms` 에서 직접 읽는다. 팀은 방장 화면 상태라 body 로 받고 검증 (팀 2개, 각 1~5명, 닉네임 1~16자, 포지션·숙련도 enum).
  - 전송 제한: 방마다 1분 창에 10회 (`get_discord_webhook_for_send`, 넘으면 `DISCORD_RATE_LIMITED`).
  - 디스코드가 404/401 → 웹훅이 삭제된 것으로 보고 연결 해제 후 `DISCORD_DISCONNECTED`. 429 → `retry_after` 를 안내.
- **F10-6** 연결 해제 `POST /api/discord/disconnect`: `clear_discord_webhook` 후 디스코드 쪽 웹훅도 삭제 (실패해도 무시).
- **F10-7** 임베드: username `naejeon-kit`, color `0xFF4655`, footer `naejeon-kit · 방 코드 ABC123`, `allowed_mentions: { parse: [] }`.
  - teams: title "팀 구성", 팀1·팀2 inline field (field name 에 점수, 줄마다 "닉네임 — 포지션")
  - map: title "이번 판 맵", description 맵 이름 (밴이 있으면 다음 줄 "밴: A · B")
  - side: description "팀1 공격 / 팀2 수비 시작"
  - all: 있는 것만 위 순서로 embeds 하나에
  - 닉네임은 디스코드 마크다운 이스케이프 + `@` 뒤 zero-width space 로 멘션(@everyone, @here, <@…>) 무력화. 필드 길이 한도를 넘으면 "…외 N명" 으로 줄인다.
- **F10-8** 비밀 값: 웹훅 id/token 은 `room_secrets` 에만. 공개 테이블 · Realtime · 참가자 화면 · API 응답으로 나가지 않는다. 방이 24시간 뒤 삭제되면 같이 삭제된다. 참가자 화면에는 디스코드 UI 가 없다.

## 6. 팀 생성 알고리즘

### 6.1 티어 점수표 (`TIER_SCORES` 상수)

| 티어 | 1 | 2 | 3 |
|---|---|---|---|
| 아이언 | 1 | 2 | 3 |
| 브론즈 | 4 | 5 | 6 |
| 실버 | 7 | 8 | 9 |
| 골드 | 10 | 11 | 12 |
| 플래티넘 | 13 | 14 | 15 |
| 다이아몬드 | 16.5 | 18 | 19.5 |
| 초월 | 21 | 22.5 | 24 |
| 불멸 | 26 | 28 | 30 |
| 레디언트 | 33 | | |

### 6.2 개인 점수
```
현티 ≠ 언랭: score = 현티점수 × 0.6 + (최티점수 ?? 현티점수) × 0.4
현티 = 언랭: score = 최티점수
```
가중치 `0.6 / 0.4`는 상수(`CURRENT_TIER_WEIGHT`, `PEAK_TIER_WEIGHT`)로 분리.

### 6.3 팀 평가
1. 10명 중 5명을 고르는 모든 조합(252개)을 만든다. 대칭 중복은 제거 가능 (첫 번째 멤버를 항상 팀1에 고정 → 126개).
2. 각 팀(5명)에 대해 **포지션 배정 평가**:
   - 5명의 순열(120개)마다, 앞 4명을 `duelist, initiator, controller, sentinel`에, 5번째를 `flex`에 배정한다고 보고:
     - `missing` = 4개 필수 포지션 중 숙련도가 `no`인 사람이 배정된 수
     - `mains` = 숙련도 `main`으로 배정된 수 (flex 제외)
   - `missing` 최소 → 그중 `mains` 최대인 배정을 그 팀의 최적 배정으로 선택.
   - flex 멤버의 추천 포지션은 본인 `main` 포지션 중 하나(없으면 `can` 중 하나), 표시는 "자유".
3. 조합 비용:
   ```
   cost = W_MISSING × (missingA + missingB)
        + W_TIER    × |sumA − sumB|
        − W_MAIN    × (mainsA + mainsB)

   W_MISSING = 1000, W_TIER = 10, W_MAIN = 1
   ```
4. 비용 오름차순 정렬 (동점은 조합 순서 유지 — 결정적, 랜덤 없음). 1번째가 최적 조합, [팀 다시 짜기] 는 상위 10개(`TEAM_OPTION_COUNT`)를 차례로 보여준다.

### 6.4 요구사항
- 순수 함수로 구현: `generateTeams(members): TeamResult` (최적 1개), `rankTeamOptions(members, limit)` (비용 순 상위 조합) — `src/features/teams/generateTeams.ts`, UI/DB 의존 없음.
- 단위 테스트 필수:
  - 전부 같은 티어 + 포지션 고르게 분포 → missing 0
  - 전략가 가능 인원 1명 → 한 팀에만 전략가, 다른 팀 경고
  - 티어 극단 분포 → 점수 합 차이가 최소인 조합
  - 입력 10명이 아니면 에러
- 실행 시간 50ms 이하 (브라우저).

## 7. 데이터 모델 (Supabase / Postgres)

> 비밀 값(`host_key`, `edit_token`)은 **anon이 SELECT할 수 없는 별도 테이블**에 둔다. Realtime은 SELECT 권한이 있는 테이블만 이벤트가 오므로, 공개 테이블에 비밀이 섞이면 그대로 노출된다.

### 7.1 공개 테이블 (anon SELECT 허용, 직접 INSERT/UPDATE/DELETE 금지)

**rooms**
| 컬럼 | 타입 | 비고 |
|---|---|---|
| id | uuid PK | |
| code | text UNIQUE | 6자리 |
| map_pool | text[] | 켜진 맵 목록 |
| map_roll_id | uuid null | 맵 랜덤 실행마다 새 값 (연출 트리거) |
| map_bans | text[] | 마지막 맵 랜덤 때 밴한 맵 (0~2개) |
| result_map | text null | 마지막 맵 랜덤 결과 |
| side_roll_id | uuid null | 공수 랜덤 실행마다 새 값 (연출 트리거) |
| side_team1 | text null | `attack` / `defense` |
| team1_ids | uuid[] null | 방장이 공유한 팀1 멤버 id 5명 (F5-7) |
| team2_ids | uuid[] null | 팀2 멤버 id 5명 |
| discord_guild_name | text null | 디스코드 연결된 서버 이름 (F10). null = 미연결, `''` = 연결됐지만 이름 모름 |
| created_at | timestamptz | |

**members**
| 컬럼 | 타입 | 비고 |
|---|---|---|
| id | uuid PK | |
| room_id | uuid FK → rooms (cascade) | |
| nickname | text | (room_id, nickname) UNIQUE |
| current_tier | text null | 예: `gold_2`, `unranked`; null = 미입력 |
| peak_tier | text null | |
| positions | jsonb | `{ "duelist": "main", "initiator": "can", ... }` |
| updated_at | timestamptz | |

### 7.2 비공개 테이블 (anon 접근 전부 금지, RPC에서만 사용)

**room_secrets**: `room_id PK`, `host_key text`, 디스코드(F10): `discord_webhook_id text`, `discord_webhook_token text`, `discord_send_window_start timestamptz`, `discord_send_count int default 0`
**member_tokens**: `member_id uuid PK → members(id) on delete cascade`, `edit_token text not null`. RLS 켜고 정책 없음.

토큰·방장 키는 `encode(extensions.gen_random_bytes(24), 'hex')` (pgcrypto).

### 7.3 RPC (SECURITY DEFINER)

모든 쓰기는 RPC로만. 각 함수는 `security definer set search_path = public` 이고 내부에서 권한을 검사한다. 실패는 `raise exception` 메시지 코드로 돌려준다 (`ROOM_NOT_FOUND`, `FORBIDDEN`, `NICKNAME_TAKEN`, `INVALID_*`).

| 함수 | 권한 | 동작 |
|---|---|---|
| `create_room()` | 누구나 | 코드 생성(충돌 시 재시도), host_key 생성 → `{ code, host_key }` 반환 |
| `upsert_member_as_host(code, host_key, member)` | 방장 | 멤버 추가/수정 |
| `bulk_add_members(code, host_key, nicknames[])` | 방장 | 일괄 등록, 건너뛴 닉네임 반환 (현재 화면에서 사용 안 함) |
| `delete_member(code, host_key, member_id)` | 방장 | 삭제 |
| `verify_host_key(code, host_key)` | 누구나 | 방장 키 확인, 틀리면 `FORBIDDEN` (F2-8) |
| `register_self(code, nickname, current_tier, peak_tier, positions)` | 누구나 | 신규 멤버 + `edit_token` 생성 → `{ member_id, edit_token }`. 방 없으면 `ROOM_NOT_FOUND`, 닉네임 중복 `NICKNAME_TAKEN` |
| `update_self(member_id, edit_token, nickname, current_tier, peak_tier, positions)` | 본인 | 토큰 일치 시 수정 + `updated_at = now()`. 불일치 `FORBIDDEN`, 닉네임 중복 `NICKNAME_TAKEN` |
| `delete_self(member_id, edit_token)` | 본인 | 토큰 일치 시 삭제 (`member_tokens` 는 cascade). 불일치 `FORBIDDEN` |
| `set_map_pool(code, host_key, maps[])` | 방장 | 맵 풀 수정 (1개 이상, 알려진 맵 키만). 아니면 `INVALID_MAP_POOL` |
| `roll_map(code, host_key, bans[])` | 방장 | bans 검증(0~2개, 중복 없이, 맵 풀 안의 맵, 아니면 `INVALID_BANS`) → 남은 맵 중 랜덤 1개 (없으면 `NO_MAPS_LEFT`) → map_bans, result_map, map_roll_id 갱신 → `{ map, roll_id }` |
| `roll_side(code, host_key)` | 방장 | side_team1 랜덤 + side_roll_id 갱신 |
| `set_teams(code, host_key, team1[], team2[])` | 방장 | 각 5명, 중복 없이, 모두 이 방 멤버여야 함 (아니면 `INVALID_TEAMS`) → team1_ids, team2_ids 저장 (F5-7) |
| `verify_host(code, host_key)` | 누구나 | 방장 키 확인 → boolean (예외 없음) |
| `set_discord_webhook(code, host_key, webhook_id, webhook_token, guild_name)` | 방장 | 웹훅 저장 + 전송 횟수 초기화, rooms.discord_guild_name 갱신. 형식이 틀리면 `INVALID_DISCORD` (F10) |
| `clear_discord_webhook(code, host_key)` | 방장 | 지우기 전 `{ id, token }` 반환 후 삭제 (서버가 디스코드 쪽 웹훅도 삭제) |
| `get_discord_webhook_for_send(code, host_key)` | 방장 | `{ id, token }` + 1분 10회 제한 (`DISCORD_RATE_LIMITED`), 미연결 `DISCORD_NOT_CONNECTED` |

> 디스코드 RPC 는 서버 라우트(`/api/discord/*`)에서만 부른다. 다만 anon 에게 execute 가 열려 있어서 방장 키를 가진 사람은 직접 호출해 웹훅 토큰을 받을 수 있다 (방장 키 유출 주의).

**동시성**
- 랜덤은 **반드시 서버(RPC 내부)** 에서. 클라이언트 랜덤 금지.

기존 멤버를 이어받는 RPC(`claim_member`)는 없다. 토큰은 등록할 때 한 번만 발급된다.

### 7.4 만료
- 24시간 지난 방 삭제. 우선순위:
  1. Supabase `pg_cron`으로 1시간마다 삭제
  2. 불가하면 `create_room()` 실행 시 만료된 방 정리
- 만료된 코드로 접근 시 "만료된 방이에요" 표시.

## 8. 실시간 동기화

- 방 화면 진입 시 Supabase Realtime으로 해당 방 데이터만 구독:
  - `members` (filter `room_id=eq.{id}`) — INSERT / UPDATE / DELETE
  - `rooms` (filter `id=eq.{id}`) — 맵 풀, 맵 결과, 공수 결과, 팀 구성, 디스코드 연결 서버 이름
- 이벤트 수신 시 TanStack Query 캐시 갱신 (`setQueryData` 또는 `invalidateQueries`).
- **구독 먼저 → 초기 조회** 순서로 (사이에 들어온 변경 누락 방지).
- 재연결 / 탭 복귀 시 재조회 (`refetchOnReconnect`, `refetchOnWindowFocus` 활성).
- 대상 테이블 Realtime 활성화 + RLS SELECT 정책 확인 (이벤트 안 오는 주원인).
- 방장 화면에 수동 [새로고침] 버튼.

**수용 기준**
- 참가자가 정보를 저장하면 방장 화면에 **2초 이내** 반영.
- 참가자 5명이 동시에 등록해도 누락 없이 전부 표시.
- 폰 화면을 껐다 켠 뒤에도 최신 상태로 복구.

## 9. 라우팅

| 경로 | 화면 |
|---|---|
| `/` | 초기 페이지 (방 파기 / 참가하기) |
| `/join/[code]` | `/room/[code]` 로 리다이렉트 |
| `/room/[code]` | 참가자 화면 |
| `/room/[code]/host` | 방장 화면 (localStorage에 유효한 host_key 필요, `#key=` fragment로 복구 가능) |
| `/api/discord/start` · `callback` · `send` · `disconnect` | 디스코드 연동 서버 라우트 (F10) |

방장 화면과 참가자 화면은 **페이지를 분리**한다. 공통 컴포넌트(멤버 카드, 맵 그리드, 결과 연출 등)는 공유하되 권한별 동작은 props로 받는다.

## 11. 비기능 요구사항

- **모바일 우선**: 대부분 폰으로 디코 보면서 접속. 360px 폭에서 가로 스크롤 없음, 탭 영역 44px 이상.
- **성능**: 첫 화면 로드 후 상호작용까지 3초 이내 (모바일 4G 기준).
- **접근성**: 포지션·숙련도는 색만으로 구분하지 않음 (아이콘/텍스트 병행). `prefers-reduced-motion` 대응.
- **보안**: 모든 쓰기 RPC 경유, 비밀 값은 비공개 테이블, 방장 키는 URL 쿼리스트링이 아닌 fragment로 전달.
- **비용**: Supabase 무료 티어 안에서 운영 (방 24시간 만료).

## 12. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 방장 키 분실 (다른 기기, 캐시 삭제) | 화면에 [방장 링크 복사] 가 없어서 복구 불가 → 새 방 (`#key=` 링크를 직접 만들어 열면 복구는 된다) |
| 참가자 기기 변경 | 새 기기에선 다시 입력 (닉네임 중복 시 방장이 기존 항목 삭제·수정) |
| 방장이 참가자 항목 삭제 | 참가자 화면은 저장된 id 를 못 찾으면 `member:{code}` 를 지우고 입력 화면으로 |
| 닉네임 중복 | 저장 거부, "이미 있는 닉네임" 표시 |
| 멤버 수 ≠ 10 | 팀 짜기 비활성 + 현재 인원 표시 |
| 티어 미입력 멤버 존재 | 팀 짜기 비활성 + 해당 멤버 강조 |
| 포지션 불충족 | 팀은 생성하되 경고 표시 |
| 밴 2개 초과 선택 | 3번째 탭은 무시 (서버도 거부) |
| 밴 0개 | 밴 없이 맵 풀 전체에서 랜덤 |
| 남은 맵 0개 | 확정 거부, 에러 |
| 밴한 맵을 맵 풀에서 끔 | 밴 선택에서도 해제 |
| 연출 중 새 결과 도착 | 진행 중 연출 취소, 새 결과로 연출 |
| 만료된 방 접근 | "만료된 방이에요" + 초기 페이지 이동 버튼 |

## 13. 구현 순서 (마일스톤)

1. **세팅**: Next.js + TS + Tailwind + TanStack Query + Supabase 클라이언트, 상수 파일
2. **DB**: 마이그레이션 (테이블, RLS, 비공개 테이블, RPC), Realtime 활성화
3. **방**: 초기 페이지, `create_room`, 입장, 방장 키 저장/복구, 링크 복사
4. **멤버**: 목록 + 실시간 구독, 방장 CRUD, 일괄 등록, 참가자 등록/본인 수정·삭제
5. **팀**: `generateTeams` + 단위 테스트 → 멤버 목록 + 팀 짜기 버튼 → 결과 UI
6. **맵**: 맵 풀 설정, 방장 밴 선택(최대 2개), `roll_map` RPC, 실시간 반영
7. **공수**: `roll_side` + 실시간 반영
8. **연출**: 공통 reveal 컴포넌트, 맵·공수에 적용, 스킵·reduced-motion
9. **공유**: 디코용 텍스트 생성·복사
10. **만료 + 마무리**: 24시간 삭제, 에러/빈 상태 UI, 모바일 점검
11. **동시성 테스트**: 일반 창(방장) + 시크릿 창 여러 개(참가자) + 폰 화면 끄고 켜기
